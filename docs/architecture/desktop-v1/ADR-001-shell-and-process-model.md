# ADR-001: Desktop Shell 与进程模型

- 状态：Proposed
- 日期：2026-03-16

## 背景
当前项目已有稳定翻译核心（`src/`）和本地 Web UI（`src/ui.ts`）。桌面化需要在不破坏核心能力的前提下提供原生桌面入口与多页面体验。

## 决策
- V1 采用“桌面壳 + 核心引擎复用”方案。
- 进程分层：
  - 渲染层：负责页面与交互
  - 应用服务层：负责任务编排、状态管理、日志聚合
  - 核心引擎层：复用 `src/` 翻译能力
- CLI 保持兼容，不与桌面层互相替代。

## 备选方案
1. 继续仅维护 Web UI：改造成本低，但桌面分发体验弱。
2. 重写核心引擎：灵活但风险高、周期长。

## 取舍结果
选择“复用核心 + 新增桌面壳”，以控制风险并缩短 V1 周期。

## 后果
- 优点：迁移成本可控，兼容现有 CLI 与配置。
- 代价：需要定义清晰 IPC 和错误模型，避免层间耦合。

## 后续动作
- 产出 IPC 接口草案与模块边界图。
- 在 `apps/desktop` 建立实现入口。
