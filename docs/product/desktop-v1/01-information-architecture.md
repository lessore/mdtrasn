# Chapter 1A 信息架构定稿（Information Architecture）

## 1. 设计原则
- 任务优先：页面围绕“完成翻译任务”而不是“展示参数”。
- 闭环优先：每个页面都明确“当前状态 -> 下一步动作”。
- 降低记忆负担：常用功能固定位置，跨页动作一致。
- 核心兼容：不破坏 CLI 与现有配置格式。

## 3. 页面职责与模块边界

## 3.1 工作台
- 主职责：进入应用后的全局总览与快速开工。
- 核心模块：
  - 快速新建任务
  - 最近任务
  - 最近结果
  - 风险提示卡
- 主操作：`新建翻译任务`

## 3.2 翻译任务
- 主职责：配置并执行单次翻译任务。
- 核心模块：
  - 输入源（文件/目录）
  - 引擎参数（Provider、模型、密钥）
  - 输出策略（路径、模式、是否自动打开）
  - 运行控制（开始/取消/重试）
- 主操作：`开始翻译`

## 3.3 结果中心
- 主职责：查看本次/最近任务结果并进行后续操作。
- 核心模块：
  - 统计卡（新增翻译/缓存命中/失败数）
  - 结果列表（成功、失败、复制资产）
  - 问题面板（可筛选与可重试）
- 主操作：`打开输出`、`失败项重试`

## 3.4 术语与规则
- 主职责：管理术语、保留词和翻译规则。
- 核心模块：
  - `preserve` 列表管理
  - `translateAs` 键值管理
  - 导入导出
  - 冲突提示
- 主操作：`保存规则`

## 3.5 历史记录
- 主职责：追踪过往任务并支持复跑。
- 核心模块：
  - 时间轴列表
  - 任务详情抽屉
  - 复跑入口
- 主操作：`按该配置复跑`

## 3.6 设置
- 主职责：系统级配置与偏好管理。
- 核心模块：
  - Provider 凭证
  - 默认输出策略
  - Typora 集成
  - 日志与诊断开关
- 主操作：`保存设置`

## 4. 跨页面对象模型
- `TranslationTask`
  - `id`, `sourcePath`, `outputPath`, `provider`, `status`, `startedAt`, `finishedAt`
- `RunSummary`
  - `translatedSegments`, `cachedSegments`, `skippedSegments`, `failures[]`, `warnings[]`
- `GlossaryProfile`
  - `preserve[]`, `translateAs{}`
- `AppSettings`
  - `defaultOutputMode`, `openInTypora`, `providerSecretsRef`

## 5. IA 决策记录
- 决策 1：采用纯工作台，不采用分步向导。
  - 原因：目标用户会高频重复操作，工作台效率更高。
- 决策 2：术语与设置分离。
  - 原因：术语是内容层规则，设置是系统层偏好，频次和影响面不同。
- 决策 3：结果中心独立成页。
  - 原因：失败恢复是高频操作，不能埋在任务页底部。
